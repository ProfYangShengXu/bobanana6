# acceptance/ —— 验收集（`实现规格.md §14` / `架构设计.md §15`）

**与 `tests/` 的区别**：`tests/` 是确定性的单元与架构守卫（无模型、无网络）；
这里是**系统级验收**，可以接真模型，但要可控。

```
acceptance/
  judge.py      判分器：三口径 + 强制覆盖声明（§14.3）
  harness.py    把一道题跑成一份 AcceptanceReport
  smoke/        3 个小任务 + baseline.json（门禁用的容差表）
  main/         同形状 × 3 域（金融 / 文献 / 日志）
  stress/       input/ 与 truth/ 【物理隔离】+ attacks.yaml
  counter/      反例集：应当【拒绝切分】的任务
  inject/       压力集 + 已知缺陷
```

## 三条不可破的口径

```
① ★ 禁合成单一总分 —— 块级 / 装配 / 归因朝不同方向动，一个总分把它们掩盖掉
② ★ 没走到的出口必须声明 —— 没被走到的出口 = 未验证的代码
③ ★ 冒烟用【通过数对比容差】—— 不用 reward 二值（会把能力波动误诊成架构回归）
```
三条都**落成了测试**（`tests/test_acceptance.py`），不是写在文档里。

## ★ ground truth 物理隔离（§14.1）

`stress/input/` 给系统，`stress/truth/` 只在评测时挂 —— **不在同一个容器里同时挂**。
不隔离时，「模型没答对」和「模型偷看了」分不开。

合成数据的两半也是这样分的：`generate.py` 把输入写进每个题目的 `input/`、
真值写进 `truth/`；`harness.run_task()` **只把 `input/` 交给运行**（`TaskRun.inputs_given`
就是用来给测试断言这一点的）。两半都**不入库**（见 `.gitignore`）：真值尤其不能入库。

## 本块建了什么、没建什么（诚实标注）

| 目录 | 本块状态 |
|---|---|
| `smoke/` | ✅ 3 道单源小题 + `baseline.json`（结构 + 加载器 + 门禁算式 + 离线 5 次实测） |
| `main/` | ✅ 1 道多块题（3 源 → 3 读 + 1 写），机制断言 + 真模型跑测 |
| `counter/` | ✅ 反例题 + 「不该拆」的机制断言（★ 但 `refuse_split` 出口**在代码里不存在**，见 `counter/README.md`） |
| `stress/` | ⬜ 只有骨架与 `attacks.yaml`（攻击清单是从 §14.2 抄下来的**计划**，没有执行器） |
| `inject/` | ⬜ 空占位：留给「发现 / 归因 / 出口」三步判据（§14.5） |

**没建的三条留给后面的块**：20–40 源的压力任务（§15.4）、攻击注入执行器（§14.2）、
基线表的真模型 5 次同窗分布（§14.6）。
