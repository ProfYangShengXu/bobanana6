## 阶段 1：LLM 基础与上下文工程（4-5 周）⭐⭐⭐⭐⭐ **【必须掌握】**

### 📚 学什么

1. **Transformer 架构深度理解**
   - Attention 机制变体（Multi-head、Attention Is All You Need）
   - 位置编码、残差连接、归一化
   - 来自 hunt:3 - Transformer / LLM 原理 占 30% 基础理论权重

2. **上下文工程（Context Engineering）**
   - Prompt 模板设计技巧
   - Few-shot learning 策略
   - CoT / ToT 推理链
   - 来自 hunt:1 - "研究 Prompt 工程、指令微调、RAG、Agent 系统等技术"

3. **Tokenizer 与 Token 编码**
   - BPE、WordPiece、SentencePiece 原理
   - Token 序列化与反序列化
   - 上下文窗口限制与扩展策略

4. **In-Context Learning 原理**
   - 提示窗口利用技巧
   - 示例工程（Example Engineering）
   - 少样本 vs 多样本测试

### 🔍 为什么这个最先学

- **核心原因**：Agent 系统的本质是 LLM 与外部工具的交互编排，如果基础不牢，后续所有 Agent 架构都是空中楼阁
- hunt:3 明确指出 LLM 原理是三大支柱之一
- 面试中会出现追问："为什么你的 Context Window 设置是 XXX？"（来自 hunt:2 面经）

### ✅ 过关标准

- [x] 能画出完整的 Transformer 架构图并讲解每个模块作用
- [x] 面试中能清晰回答：LLM 推理延迟受哪些因素影响？如何优化？
- [x] 能设计并调试一套上下文压缩策略（滑动窗口 + 摘要 + 关键信息提取）
- [x] 能举例说明 CoT/ToT 在 Agent 中的具体应用场景

### ⏱️ 时间规划

- **周 1-2**：Transformer + Token 原理，完成一篇技术博客
- **周 3-4**：Context Engineering，搭建一个带长对话记录的实验系统
- **周 5（可选）**：深入学习 In-Context Learning 边界条件

### ⚡ 优先级标注

- **必须项**：Transformer 架构理解（80% 覆盖）、Context Engineering（70% 覆盖）
- **加分项**：Tokenizer 细节、ICL 进阶技巧（50% 覆盖）

## 阶段 2：Agent 框架与编排系统（4-6 周）⭐⭐⭐⭐⭐ **【必须掌握】**

### 📚 学什么

1. **LangChain 核心组件**
   - Chains 与 State Management
   - Prompts 模板系统与 Variables
   - Memory 模块（ChatMemory、BufferMemory 等）

2. **LangGraph / State Machine 编排**
   - DAG 图构建与状态流转
   - Human-in-the-loop 设计
   - 条件分支与重试机制
   - 来自 hunt:5 - 534 个 Agent 列表中 LangGraph 是主流选择

3. **LlamaIndex 知识图谱与 RAG**
   - Vector Store + Metadata
   - RecursiveRetriever 多路召回
   - ReRank 精细化过滤

4. **多 Agent 协作模式**
   - Master-Detail 架构
   - Parallel + Sequential 组合
   - A2A 协议（Agent-to-Agent）

### 🔍 为什么这个最先学

- hunt:5 明确指出"agent 框架（LangGraph 领先）"是跨地区共同信号
- hunt:2 面经中提到"A2A 与 MCP 区别"是字节考察重点（16 题中的第 12 题）
- 2026 年 5 月 LangChain 市场报告：34% 份额，这是中坚力量

### ✅ 过关标准

- [x] 能独立搭建一个 LangGraph 多 Agent 系统，支持主从协作
- [x] 能实现 Agent 间的调用链路与状态持久化
- [x] 能处理 Agent 死循环和超时重试机制
- [x] 能对比 LangChain vs LangGraph vs CrewAI vs AutoGen 的选型理由（来自 hunt:5）

### ⏱️ 时间规划

- **周 1-2**：LangChain 基础 + 记忆模块实战
- **周 3-4**：LangGraph 多 Agent 编排，实现主从协作
- **周 5-6**：LlamaIndex 深度 RAG，多路召回 + ReRank

### ⚡ 优先级标注

- **必须项**：LangGraph（60%+ 市场占比）、LangChain 记忆模块（70% 覆盖）
- **加分项**：CrewAI、AutoGen、自定义 Agent 框架（hunt:5 提及 534 个 Agent 岗位中框架对比）

## 阶段 3：工具调用与 MCP 框架（3-4 周）⭐⭐⭐⭐ **【必须掌握】**

### 📚 学什么

1. **Function Calling 深化**
   - Schema 设计与自动生成
   - 流式调用与响应处理
   - 失败重试与错误降级

2. **MCP（Model Context Protocol）**
   - 与 Tool Server 通信协议
   - 权限配置与沙箱隔离
   - 来自 hunt:1 - MCP 是 2026 年增速最快的单一技能
   - 来自 hunt:2 面经 - A2A 与 MCP 是字节考察新热点

3. **技能系统（Skills / RAG-Agent）**
   - 基于检索的 Agent 技能
   - 技能优先级排序
   - 技能冲突解决（Priority-based vs Time-based）

### 🔍 为什么这个必须先学

- hunt:1 明确指出 MCP 是 2026 年增速最快的单一技能（2026-05-02 调研）
- hunt:2 面试中专门考察"A2A 与 MCP 区别"（第 12 题，是字节 2025-03-22 面经）
- hunt:1 调研显示：Python + LangChain/LangGraph + RAG + **MCP** + Function Calling 是硬性要求高度趋同

### ✅ 过关标准

- [x] 能自定义 MCP Server，实现文件读写与数据库查询
- [x] 安全边界设计：权限配置、数据脱敏、调用限制
- [x] 能处理 Function Calling 的超时、失败、重试场景
- [x] 能设计 Skill 管理系统，支持动态注册与版本控制

### ⏱️ 时间规划

- **周 1-2**：Function Calling 深化 + MCP 协议基础
- **周 3-4**：MCP Server 实战，实现多个工具服务

### ⚡ 优先级标注

- **必须项**：Function Calling 流式调用（80% 覆盖）、MCP 协议（高增长技能）
- **加分项**：Skill 系统、权限细粒度控制

## 阶段 4：上下文管理与长期记忆系统（3-4 周）⭐⭐⭐⭐ **【必须掌握】**

### 📚 学什么

1. **Vector DB 选型与优化**
   - FAISS、Milvus、Chroma、Qdrant 对比
   - 索引策略（HNSW、IVF）
   - 批量写入与查询优化

2. **记忆压缩策略**
   - 滑动窗口（Sliding Window）
   - 关键信息提取（Key Event Extraction）
   - P1-P3 重要性分级存储

3. **长期记忆架构**
   - 分层缓存（短期 LRU / 中期 Semantic / 长期 Full-text）
   - 向量知识库 + 文本索引 + 元数据标签
   - 来自 hunt:2 面经 - "多模态的用户信息怎么存储和使用"是考察点 2

### 🔍 为什么这个必须先学

- hunt:2 真实面经（字节）考察："多模态的用户信息怎么存储和使用"（第 2 题）、"较长较多的上下文怎么解决"（第 14 题）
- 多轮对话系统没有记忆，只能是 Chatbot，不是 Agent
- hunt:3 能力模型中"Agent 框架"占 30% 权重

### ✅ 过关标准

- [x] 能设计一个 Context Compressor，支持滑动窗口 + 摘要
- [x] 能实现记忆的重要性分级（P1 关键事件永久存储，P2 短期缓存）
- [x] 能处理上下文污染问题（相似对话干扰）
- [x] 能对比不同 Vector DB 在海量数据下的表现

### ⏱️ 时间规划

- **周 1-2**：Vector DB 选型实战，搭建一个带记忆的 Agent
- **周 3-4**：记忆压缩系统设计，支持长对话的平滑过渡

### ⚡ 优先级标注

- **必须项**：Vector DB 查询优化（70% 覆盖）、记忆压缩（60% 覆盖）
- **加分项**：多模态记忆、元数据增强检索

## 📝 项目建议（2.5-3 个月，全职可完成）

> **目标**：做一个"智能办公助手"，能讲清记忆机制、工具调用、上下文管理三大核心点

### 🎯 项目设计方案

**核心功能模块：**

1. **记忆系统**
   - 长对话总结（Key Event Extraction）
   - 分层缓存（短期 LRU + 中期向量存储 + 长期全文索引）
   - 上下文压缩（滑动窗口 + 摘要）
   - **面试可讲**：为什么选这种存储方式？P1/P2/P3 如何定义？

2. **工具调用链路**
   - MCP Server（文件、数据库、API）
   - Function Calling 流式调用
   - 权限配置与安全沙箱
   - **面试可讲**：如何设计权限模型？如何避免越权访问？如何重试？

3. **多 Agent 协作**
   - 主从架构（1 个主导 Agent + 多个工具 Agent）
   - LangGraph 编排
   - 状态持久化与人类介入点
   - **面试可讲**：主 Agent 如何决策？从 Agent 如何协作？如何避免死循环？

4. **评测架构**
   - 单元测试（核心用例覆盖率 80%）
   - 端到端测试（完整业务流程）
   - 失败案例与回归测试（来自 hunt:1"项目常用的 AI 测试用例"）

### 📊 项目产出清单

| 模块 | 技术选型 | 面试亮点 |
|------|---------|---------|
| 记忆 | Chroma + 滑动窗口 + 关键事件提取 | 解释为什么选这个方案？复杂度？ |
| 工具 | MCP + LangChain + Schema 自动生成 | 权限如何设计？如何保证安全？ |
| 编排 | LangGraph + Dogpile 状态管理 | Show how state persists |
| 测试 | pytest + 断言 + 自定义 harness | Show 80% 覆盖率 |

### 🎤 面试可回答

> "我的记忆系统采用分层设计：短期用 LRU 缓存实时对话上下文（P3），中期用 Chroma 向量存储关键事件（P2），长期用 MySQL 存储完整对话记录（P1）。Context Compressor 基于滑动窗口 + 关键信息提取，确保在 128k token 限制下保持关键信息。"
